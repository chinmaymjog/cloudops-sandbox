# Architecture

## What This Is

A local-cloud style platform for testing infrastructure components,
observability stacks, and automation tools, with one consistent ingress
and environment model. See the architecture diagram in `README.md`.

## How It Works

- **Traefik** is the single ingress entry point - all routing is
  host-based (`<service>.<APP_DOMAIN>`), with TLS handled per the
  chosen setup mode (see README).
- Each tool lives in its own `stacks/<name>/` directory with its own
  `docker-compose.yml` - no monolithic compose file. Service configuration
  lives in Compose YAML; the root `.env` supplies interpolated values.
- `make up` creates the shared `control-plane` network if needed, then runs
  `docker compose --env-file .env -f stacks/<name>/docker-compose.yml up -d`
  for each stack on the Makefile's `STACKS` line, in order. There are no
  other scripts.
- The root `.env` holds every value and secret. Secrets are generated by
  hand with `openssl rand` and pasted in.
- Each app that uses PostgreSQL gets its own user and database, created by
  hand with `docker exec postgresql psql` (README, Quick Start step 3).
- State persists via named Docker volumes.

## Key Decisions

- **Decision:** Modular stack directories under `stacks/<name>/`, not a
  single compose file; service runtime configuration is defined in each
  stack's Compose YAML.
  **Why:** Scales to many tools without one file becoming unmanageable;
  each stack owns its Compose definition while sharing root deployment values.
  **Revisit if:** Stack count causes real orchestration overhead.

- **Decision:** Standardize ingress on Traefik with a wildcard host
  strategy (`<service>.$APP_DOMAIN`), not per-stack host ports.
  **Why:** One consistent access pattern for local and remote runs,
  instead of remembering a different port per tool.
  **Revisit if:** Routing conflicts or TLS management overhead becomes
  the dominant pain point.

- **Decision:** Add `stacks/cloudflared` (Cloudflare Tunnel) as an
  optional public ingress path in front of Traefik.
  **Why:** The lab commonly runs behind NAT/CGNAT with no static public
  IP. A tunnel makes an outbound-only connection to Cloudflare's edge,
  so nothing needs to be opened on the router - unlike port-forwarding,
  which also just doesn't work under CGNAT.
  **Revisit if:** Per-app tunnel behavior (different origin
  ports/protocols per stack) is needed that a single wildcard route
  can't express.

- **Decision:** Documented commands instead of automation. Removed the
  setup/startup/shutdown scripts, per-stack `.env` generation, the secret
  generator, the PostgreSQL init and sync scripts, and Compose profiles.
  `make up` is a short loop over an explicit `STACKS` list.
  **Why:** Adding a service had turned into editing a template, a profile,
  a script's group list, and an init script - cumbersome even for the
  repo's owner, so worse for anyone else. Each layer of automation also
  hid a failure: the profile split broke `make up` with `no service
  selected` in a way that took reading three files to understand. Now
  adding a service is a Compose file, a few `.env` lines, and optionally
  two `docker exec` commands - every step visible and runnable by hand.
  **Revisit if:** The same manual step is being repeated often enough, by
  enough people, that a script would clearly be simpler than the commands
  it replaces.

## Known Risks / Rough Edges

- Forgetting to create an app's database (Quick Start step 3) leaves that
  app in a restart loop with `password authentication failed for user
  "<name>"` in its logs (the user doesn't exist yet). Creating the user and
  database fixes it - the container recovers on its next restart, no
  `make up` needed.
- `cloudflared` isn't on the default `STACKS` list; it's started with
  `make up STACKS=cloudflared` once a tunnel token is set.
- A variable missing from `.env` is reported by Docker Compose as a warning
  and becomes an empty string - check `make up` output after adding a stack.
- No Kubernetes runtime in scope - that's `k3s-argocd-sandbox`.
- Tracing isn't standardized; logs and Prometheus metrics are the
  current observability surface.
